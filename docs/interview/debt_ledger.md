# Debt ledger

Every shortcut in this code that was taken on purpose carries a `# ponytail:` comment saying where it stops working and what to do then. This page lists all 16 of them (from `feedback_ingest/`; `scripts/` has none) so you can answer "what would you do next, and why didn't you do it yet?" Line numbers were re-checked against the code after the Fleet 2 and tailoring commits.

The short answer to "why not yet" is the same for every row: each one has a known limit we have not hit at take-home scale, and the fix costs more code, more moving parts, or a Postgres we do not run yet. Each row says which.

## Top three I would do first

1. **#6, the Discourse 10-page cap (`discourse_pull.py:29`).** It is the only one that can leave a source stuck failing until a person steps in, and a busy forum is a normal event.
2. **#1, migrations (`db.py:39`).** The very first schema change on a real database turns "delete the db file" into data loss, so it has to land before any customer data exists.
3. **#12, the shared bootstrap token (`tenants.py:18`).** It is the main security gap on the list: one leaked secret is enough to create tenants, with nobody able to tell who did it.

16 markers, 1 with no upgrade trigger (#4, on purpose: the real-database test covers it).

## Kept on purpose

These came up in review and were kept, with the reason. None has a `# ponytail:` marker, so they are listed here.

- **Adapter-level `limit` and `lease_seconds` guards** (`claim`, `list_by_status`, `list_for_tenant` raise below 1). The API already validates them, but SQLite treats `LIMIT -1` as "no limit", and the adapters are also called from scripts, so the guard stays where the query is built.
- **Per-connector `verify_signature` hook** (ADR-003 ruling 3). Every connector delegates to the HMAC default today; the hook is where Intercom's SHA-1 or Discourse's prefixed header goes, so removing it would move the extension point into the router.
- **Three Discourse modules** (`discourse.py`, `discourse_models.py`, `discourse_pull.py`). Together they are about 200 lines; one file would break the 120-line cap, so the split stays.
- **No per-tenant fairness or quotas, no rate limit.** One tenant's burst sits ahead of others in the shared `raw_events` queue (the noisy-neighbour risk). The upgrade is round-robin claiming by tenant, or per-tenant partitions, plus a per-tenant rate limit.
- **No timestamp in the webhook signature.** A captured, correctly signed request can be sent again. It changes nothing (it is a duplicate raw event), but a signed timestamp with a short window is the fix if replays matter.
- **Webhook secrets stored as plain text** in the `sources` table (they must be readable to check the HMAC). Encrypt them at rest, or keep them in a secret manager, before real customers.
- **Global queue counts on `/health`** with no auth. They hold no tenant data; per-tenant counts are behind the API key at `GET /admin/queue`.
- **The Discourse post URL is built from the upstream `topic_slug` as given.** It is display data, never fetched by us.
- **`TransformError` keeps its name** (not renamed to `PermanentError`): the rename would touch every connector for no behaviour change.
- **`kind` is derived from `source_type`** (or the record type for `custom`) instead of being declared on each connector: one table in `domain/models.py` is easier to read than five class attributes.
- **Pull treats permanent and transient upstream errors the same**: stop, keep the cursor, retry next tick. A permanent error (for example a 404 `base_url`) therefore retries every tick and shows in `failing_sources` until someone fixes the config.
