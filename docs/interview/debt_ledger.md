# Debt ledger

Every shortcut in this code that was taken on purpose carries a `# ponytail:` comment saying where it stops working and what to do then; this page lists all 16 of them (from `feedback_ingest/` and `scripts/`) so you can answer "what would you do next, and why didn't you do it yet?"

The short answer to "why not yet" is the same for every row: each one has a known limit we have not hit at take-home scale, and the fix costs more code, more moving parts, or a Postgres we do not run yet. Each row says which.

## Top three I would do first

1. **#6, the Discourse 10-page cap (`discourse_pull.py:26`).** It is the only one that can leave a source stuck failing until a person steps in, and a busy forum is a normal event.
2. **#1, migrations (`db.py:30`).** The very first schema change on a real database turns "delete the db file" into data loss, so it has to land before any customer data exists.
3. **#12, the shared bootstrap token (`tenants.py:18`).** It is the one security gap on the list, and one leaked secret is enough to create tenants with nobody able to tell who did it.

16 markers, 1 with no upgrade trigger (#4, on purpose: the real-database test covers it).

## Kept on purpose

These looked like trims in the final audit and were kept, with the reason:

- **Adapter-level `limit` and `lease_seconds` guards** (`claim`, `list_by_status`, `list_for_tenant` raise below 1). The API already validates them, but SQLite treats `LIMIT -1` as "no limit", and the adapters are also called from scripts, so the guard stays where the query is built.
- **Per-connector `verify_signature` hook** (ADR-003 ruling 3). Every connector delegates to the HMAC default today; the hook is where Intercom's SHA-1 or Discourse's prefixed header goes, so removing it would move the extension point into the router.
- **Three Discourse modules** (`discourse.py`, `discourse_models.py`, `discourse_pull.py`). Together they are about 210 lines; one file would break the 120-line cap, so the split stays.
